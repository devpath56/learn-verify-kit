The three competencies

C1 · Who terminates the loop L2

Size the cap from the p99 of healthy runs. Never from the incident.

A summarizer times out at 190 turns. The team sets max_turns: 200. That is the number that just failed, so it licenses 199 turns of the same runaway.

ICP1 readsAn un-budgeted spend authorization with no named owner. A cap nobody is paged for is a config value, not a control.
ICP2 readsThe blast radius of one demo. There is no p99 yet — use the cost of one bad run you can absorb.

C2 · Framework is not harness L2

Anything that must survive the swap is harness. Everything else is framework.

The failure is silent, not loud. After the swap the run still succeeds — it is simply no longer governed, so no pass/fail test has anything to assert on.

ICP1 readsA control implemented as a framework callback was never a control. Name the team that owns it after the swap.
ICP2 readsPick the framework last. Direct API calls until the loop itself is the bottleneck.

C3 · The undeclared model swap L1

Log the model that answered, never the model you asked for.

The request carries an alias, gpt-4o. The response carries a resolved id, gpt-4o-2024-11-20. Record the alias only and a provider rotation is invisible by construction — the field never changes, so no alert can exist for it. This is a missing dimension, not a missing alert.

ICP1 readsAn unpinned alias is an un-reviewed dependency upgrade shipping continuously to production. Pin it, gate the bump behind evals.
ICP2 readsPinning costs you the improvements too. Pin nothing, log the resolved id, name the day quality moved.

201 uses Recognition-Primed Decision as its frame: read the situation as typical, take the one action it hands you, then simulate where it breaks. Five slots per answer — cues · expectancies · plausible goal · typical action · killer simulation. An answer missing the killer simulation is a 101 answer with confidence added.

How progress is measured

  • slope = (hit_rate now − hit_rate prev) ÷ days between. Units: hit-rate points per day.
  • mechanism_share = mechanism misses ÷ total misses. The packet target is to drive this down.
  • Why two. Hit rate can rise while mechanism_share stays flat, which means the questions got easier, not that the learner got better. A rise with a flat mechanism_share is treated as suspect.

Source policy

AcceptedPractitioner trade books, personal engineering blogs, conference talks. Nygard · Google SRE · Majors, Fong-Jones & Miranda · Winters et al. · Hyrum Wright · Beck · Ousterhout · Larson · Reilly · Anthropic Engineering · Hickey · Metz · Yegge.
Rejected by ruleJournal papers, standards bodies (ISO, IEEE, ACM proceedings), vendor marketing pages. ICP1 does not cite them in review; ICP2 has never opened one.

One declared exception: Gary Klein's RPD is the method frame for the 201 cases, not practitioner material about agents, and it is not taught as content.
